What’s happening behind the request?

  1. ProducerA synthetic order event
  2. API + PostgreSQLSave before accepting
  3. WorkerSign, deliver, retry
  4. ReceiverApply the effect once

Demo retries wait 2, 4, 8 and 12 seconds, with at most five attempts. Production uses longer delays with jitter. Repeated HTTP delivery is possible; the example receiver deduplicates its database effect.

Updates arrive every two seconds and stop at completion or after two minutes. You can refresh manually. Run access lasts one hour and stays only in this tab’s memory; reloading the page clears it.
